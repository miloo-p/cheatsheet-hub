JavaScript Spickzettel

Die gängigsten Konzepte und Muster, jedes in zwei Schreibweisen. Beide Varianten machen exakt dasselbe. Die kurze siehst du in modernem Code und in React ständig, die ausführliche zeigt Schritt für Schritt, was dabei passiert. Unter jedem Beispiel klappt eine Erklärung auf: ein Bild zum Merken, der Ablauf, der typische Fehler und eine Selbsttest-Frage. Die Doku-Links führen zu MDN auf Deutsch, mit (EN) markierte Links zur englischen React-Doku.

Grundlagen basics

Was in jeder Zeile Code steckt.

const vs let#

Standard ist const. let brauchst du nur, wenn die Variable später einen neuen Wert bekommt, wie in der ausführlichen Variante.

Kurz 
const label = count > 0 ? "voll" : "leer";
Ausführlich 
let label;
if (count > 0) {
  label = "voll";
} else {
  label = "leer";
}
Doku constletBedingter Operator ? :
Erklärung

Vorstellung

Stell dir eine Variable wie ein Etikett vor, das an einem Wert klebt. const heißt: Das Etikett wird nie umgeklebt. let heißt: Es darf später an einen anderen Wert wandern.

Was passiert, Schritt für Schritt

  1. Die Kurzform nutzt den ternären Operator bedingung ? wennJa : wennNein. Er ist ein Ausdruck und liefert also direkt einen Wert.
  2. Weil der Wert sofort feststeht, kann label eine const sein.
  3. In der ausführlichen Form ist if/else eine Anweisung, kein Ausdruck. Deshalb wird label erst leer angelegt und später befüllt. Dafür braucht es let.

Typischer Fehler

const macht Arrays und Objekte nicht unveränderlich: const list = []; list.push(1) ist erlaubt, nur list = [...] nicht. Und var ignoriert Blöcke, deshalb nicht mehr verwenden.

Wann welche Schreibweise?

Ternär für einfache Entweder-oder-Werte. Sobald es mehr als zwei Fälle oder mehrere Anweisungen pro Fall gibt, ist if/else lesbarer. Verschachtelte Ternäre vermeiden.

Selbsttest

Warum funktioniert const label; if (x) label = "a"; nicht?

Lösung zeigen

const muss bei der Deklaration sofort einen Wert bekommen und kann danach nicht neu zugewiesen werden. Hier brauchst du let oder einen Ternär.

Truthy / Falsy und ===#

Falsy sind nur false, 0, "", null, undefined, NaN (plus Exoten wie -0 und 0n). Die Kurzform nutzt das aus, die ausführliche prüft explizit. Immer === statt ==.

Kurz 
if (items.length) { render(items); }
if (!name) { showError("Name fehlt"); }
Ausführlich 
if (items.length > 0) {
  render(items);
}
if (name === "" || name === null || name === undefined) {
  showError("Name fehlt");
}
Doku TruthyFalsyStrikte Gleichheit ===Gleichheitsvergleiche
Erklärung

Vorstellung

In jedem if fragt JavaScript insgeheim: Fühlt sich dieser Wert wie Ja oder wie Nein an? Nur eine Handvoll Werte fühlt sich wie Nein an, alles andere zählt als Ja.

Was passiert, Schritt für Schritt

  1. items.length ist eine Zahl. 0 ist falsy, jede andere Zahl truthy. if (items.length) bedeutet also dasselbe wie items.length > 0.
  2. !name dreht den Wahrheitswert um: wahr, wenn name falsy ist, also leer, null oder undefined.
  3. == wandelt vor dem Vergleich Typen um (0 == "" ist true). === vergleicht Wert und Typ ohne Überraschungen.

Typischer Fehler

Leere Arrays und Objekte sind truthy, if ([]) ist immer wahr. Bei Arrays deshalb .length prüfen. Umgekehrt schlägt if (!count) auch bei count = 0 an, obwohl 0 ein gültiger Wert sein kann.

Wann welche Schreibweise?

Kurzform für die Frage, ob überhaupt etwas da ist. Ausführlich, wenn 0 oder "" gültige Werte sind und nicht als fehlend gelten dürfen.

Selbsttest

Ist if ({}) wahr oder falsch? Und if ("0")?

Lösung zeigen

Beide sind wahr. Ein leeres Objekt ist trotzdem ein Objekt, und "0" ist ein nicht-leerer String.

Template Literals#

Backticks mit ${} statt Strings mit + zusammenzukleben.

Kurz 
const msg = `Hallo ${name}, du hast ${cart.length} Artikel.`;
Ausführlich 
const msg = "Hallo " + name + ", du hast " + cart.length + " Artikel.";
Doku Template Literals
Erklärung

Vorstellung

Ein Template Literal ist ein Lückentext. Der Text steht fest, und in die ${}-Lücken setzt JavaScript zur Laufzeit die Werte ein.

Was passiert, Schritt für Schritt

  1. Backticks statt Anführungszeichen markieren den Lückentext.
  2. In ${} steht ein beliebiger Ausdruck: Variable, Rechnung, Funktionsaufruf oder Ternär.
  3. Das Ergebnis wird automatisch in Text umgewandelt und eingesetzt.
  4. Zeilenumbrüche im Template bleiben erhalten, ohne \n.

Typischer Fehler

Normale Anführungszeichen benutzen: "Hallo ${name}" gibt wörtlich das Dollarzeichen aus. Und beim Verketten mit +: "Summe: " + 1 + 2 ergibt "Summe: 12", weil von links nach rechts zu Text verkettet wird.

Wann welche Schreibweise?

Template Literals, sobald eine Variable im Text vorkommt. Die +-Variante solltest du lesen können, weil sie in älterem Code überall steht.

Selbsttest

Was ergibt "Summe: " + 1 + 2 und was ein Template mit Summe: ${1 + 2}?

Lösung zeigen

Das erste ergibt Summe: 12, das Template rechnet zuerst und ergibt Summe: 3.

Optional Chaining ?. und ??#

?. bricht bei null/undefined ab statt zu crashen. ?? setzt einen Standardwert nur bei null/undefined, nicht bei 0.

Kurz 
const city = user?.address?.city;
const qty = input ?? 1;
user.onSave?.();
Ausführlich 
let city = undefined;
if (user && user.address) {
  city = user.address.city;
}

let qty;
if (input === null || input === undefined) {
  qty = 1;
} else {
  qty = input;
}

if (typeof user.onSave === "function") {
  user.onSave();
}
Doku Optional Chaining ?.Nullish Coalescing ??
Erklärung

Vorstellung

?. ist ein vorsichtiger Schritt im Dunkeln: Bevor du weitergehst, prüfst du, ob da Boden ist. Fehlt er, bleibst du stehen und bekommst undefined statt eines Absturzes.

Was passiert, Schritt für Schritt

  1. Ohne ?. wirft user.address.city einen TypeError (Cannot read properties of undefined), wenn address fehlt.
  2. user?.address?.city prüft vor jedem Punkt, ob links davon null oder undefined steht. Wenn ja, ist der ganze Ausdruck sofort undefined.
  3. a ?? b liefert a, außer a ist null oder undefined. Dann kommt b.
  4. fn?.() ruft die Funktion nur auf, wenn es sie gibt. Praktisch für optionale Callback-Props.

Typischer Fehler

?? mit || verwechseln. input || 1 ersetzt auch 0 und "" durch 1, weil || auf falsy prüft. Bei Mengen, Preisen und Indizes fast immer ?? nehmen.

Wann welche Schreibweise?

?. bei Daten, die unvollständig sein können, z.B. aus APIs. Nicht überall verstreuen: Wenn ein Wert immer da sein muss, soll ein Fehler ruhig sichtbar werden.

Selbsttest

Was ergibt 0 ?? 5, und was ergibt 0 || 5?

Lösung zeigen

0 ?? 5 ergibt 0, weil 0 weder null noch undefined ist. 0 || 5 ergibt 5, weil 0 falsy ist.

Funktionen functions

Funktionen sind Werte: man kann sie speichern, übergeben und zurückgeben.

Arrow Functions#

Ohne {} wird der Ausdruck automatisch zurückgegeben (implizites return). Ein Objekt muss dann in (). Arrow Functions haben kein eigenes this.

Kurz 
const add = (a, b) => a + b;
const square = n => n * n;
const makeUser = name => ({ name });
Ausführlich 
function add(a, b) {
  return a + b;
}
function square(n) {
  return n * n;
}
function makeUser(name) {
  return { name: name };
}
Doku PfeilfunktionenFunktionen (Leitfaden)
Erklärung

Vorstellung

Eine Arrow Function ist eine Funktion in Kurzschrift: links vom Pfeil die Eingabe, rechts das Ergebnis. Lies (a, b) => a + b als: a und b werden zu a + b.

Was passiert, Schritt für Schritt

  1. Ohne geschweifte Klammern nach dem Pfeil wird der Ausdruck automatisch zurückgegeben (implizites return).
  2. Mit geschweiften Klammern ist es ein normaler Funktionskörper. Dann musst du return wieder selbst schreiben.
  3. Bei genau einem Parameter dürfen die runden Klammern weg: n => n * n.
  4. Soll direkt ein Objekt zurückkommen, braucht es runde Klammern drumherum. Sonst hält JavaScript {} für den Funktionskörper.

Typischer Fehler

x => { x * 2 } gibt undefined zurück, weil mit den geschweiften Klammern das implizite return wegfällt. Außerdem: Als Methode in einem Objekt zeigt this in einer Arrow Function nicht auf das Objekt.

Wann welche Schreibweise?

Arrow Functions für kurze Callbacks und React-Komponenten. function für Methoden, die this brauchen, und für Funktionen, die schon vor ihrer Definition aufgerufen werden (Hoisting).

Selbsttest

Was gibt const f = () => { name: "Lea" }; f() zurück?

Lösung zeigen

undefined. Die geschweiften Klammern sind ein Funktionskörper ohne return. Richtig wäre () => ({ name: "Lea" }).

Default- und Rest-Parameter#

Standardwerte direkt in der Signatur, beliebig viele Argumente mit ... als Array einsammeln.

Kurz 
const greet = (name = "Gast") => `Hi ${name}`;

const sum = (...nums) => nums.reduce((a, b) => a + b, 0);
sum(1, 2, 3); // 6
Ausführlich 
function greet(name) {
  if (name === undefined) {
    name = "Gast";
  }
  return "Hi " + name;
}

function sum(...nums) {
  let total = 0;
  for (const n of nums) {
    total = total + n;
  }
  return total;
}
Doku Default-ParameterRest-Parameter
Erklärung

Vorstellung

Ein Default-Parameter ist ein Ersatz für den Fall, dass der Aufrufer nichts mitbringt. Ein Rest-Parameter ist ein Sammelkorb, der alle übrigen Argumente in ein Array packt.

Was passiert, Schritt für Schritt

  1. name = "Gast" greift nur, wenn das Argument undefined ist, also weggelassen wurde.
  2. ...nums sammelt alle übergebenen Argumente in ein echtes Array namens nums.
  3. Darauf funktionieren alle Array-Werkzeuge, z.B. reduce oder for...of.

Typischer Fehler

Der Default greift nicht bei null: greet(null) ergibt Hi null. Und der Rest-Parameter muss immer der letzte sein, (...a, b) ist ein Syntaxfehler.

Wann welche Schreibweise?

Defaults gehören in die Signatur, dann sieht man beim Lesen sofort, was optional ist. Die Prüfung im Funktionskörper brauchst du nur für kompliziertere Regeln.

Selbsttest

Was ergibt greet(""), wenn der Default "Gast" ist?

Lösung zeigen

Hi mit leerem Namen. Ein leerer String ist nicht undefined, also greift der Default nicht.

Closures#

Die innere Funktion merkt sich count aus der äußeren Funktion, auch nachdem diese längst fertig ist.

Kurz 
const createCounter = () => {
  let count = 0;
  return () => ++count;
};
const next = createCounter();
next(); // 1
next(); // 2
Ausführlich 
function createCounter() {
  let count = 0;

  function increment() {
    count = count + 1;
    return count;
  }

  return increment;
}
const next = createCounter();
next(); // 1
next(); // 2
Doku Closures
Erklärung

Vorstellung

Eine Closure ist ein Rucksack: Wenn eine Funktion entsteht, packt sie die Variablen ihrer Umgebung ein und trägt sie überallhin mit, auch wenn die Umgebung längst verschwunden ist.

Was passiert, Schritt für Schritt

  1. createCounter() legt count = 0 an und gibt die innere Funktion zurück.
  2. Normalerweise wäre count nach dem Ende von createCounter weg.
  3. Weil die innere Funktion count benutzt, bleibt die Variable in ihrem Rucksack erhalten.
  4. Jeder Aufruf von next() greift auf genau dieses count zu und erhöht es.
  5. Ein zweites createCounter() erzeugt einen neuen, unabhängigen Rucksack mit eigenem count.

Typischer Fehler

Zu glauben, count sei global oder geteilt. Zwei Counter zählen unabhängig. In React begegnet dir die Kehrseite als Stale Closure: Ein Callback in useEffect hat sich einen alten State-Wert gemerkt.

Wann welche Schreibweise?

Beide Varianten sind gleichwertig. Die ausführliche mit benannter innerer Funktion zeigt beim Lernen deutlicher, dass hier eine Funktion zurückgegeben wird.

Selbsttest

Was geben a(), a(), b() aus, wenn a = createCounter() und b = createCounter()?

Lösung zeigen

1, 2, 1. b hat seinen eigenen Rucksack mit eigenem count.

Higher-Order Functions#

Funktionen, die eine Funktion zurückgeben oder annehmen. Doppelte Pfeile f => n => bedeuten: Funktion gibt Funktion zurück.

Kurz 
const multiplier = factor => n => n * factor;
const double = multiplier(2);
double(5); // 10
Ausführlich 
function multiplier(factor) {
  function multiply(n) {
    return n * factor;
  }
  return multiply;
}
const double = multiplier(2);
double(5); // 10
Doku Callback-FunktionFirst-Class Functions
Erklärung

Vorstellung

Eine Higher-Order Function ist eine Funktionsfabrik: Du gibst eine Einstellung hinein, z.B. Faktor 2, und bekommst eine fertig konfigurierte Funktion heraus.

Was passiert, Schritt für Schritt

  1. multiplier(2) wird aufgerufen, factor ist 2.
  2. Zurück kommt keine Zahl, sondern eine neue Funktion, die factor per Closure kennt.
  3. double(5) ruft diese neue Funktion auf: 5 mal 2 ergibt 10.
  4. In der Kurzform steht jeder Pfeil für eine Funktion. factor => n => ... heißt: Nimm factor und gib eine Funktion zurück, die n nimmt.

Typischer Fehler

multiplier(2, 5) aufrufen und 10 erwarten. Das zweite Argument wird ignoriert, und das Ergebnis ist eine Funktion. Richtig ist multiplier(2)(5).

Wann welche Schreibweise?

Doppelte Pfeile siehst du oft in Event-Handlern (id => () => remove(id)) und in Express-Middleware. Wenn es dich verwirrt, schreib es zuerst ausführlich hin.

Selbsttest

Welche Higher-Order Functions benutzt du schon ständig, ohne sie so zu nennen?

Lösung zeigen

map, filter, find, reduce, some, every, forEach und sort nehmen alle eine Funktion als Argument. Ebenso addEventListener und setTimeout.

Arrays frontend-kritisch

Fast jede Liste im UI läuft über diese Methoden. Die ausführliche Variante zeigt, dass dahinter nur eine Schleife steckt.

map: transformieren#

Neues Array mit gleicher Länge, jedes Element umgewandelt. In React: Daten zu JSX.

Kurz 
const names = users.map(u => u.name);

// React
users.map(u => <li key={u.id}>{u.name}</li>)
Ausführlich 
const names = [];
for (let i = 0; i < users.length; i++) {
  names.push(users[i].name);
}

// oder mit map, aber ausgeschrieben
const names2 = users.map(function (user) {
  return user.name;
});
Doku Array.prototype.map()
Erklärung

Vorstellung

map ist ein Fließband: Jedes Element läuft einmal durch dieselbe Maschine, deine Funktion. Am Ende liegt ein neues Band mit genauso vielen umgewandelten Teilen.

Was passiert, Schritt für Schritt

  1. map legt intern ein neues, leeres Array an.
  2. Für jedes Element ruft es deine Funktion auf, mit dem Element und dessen Index.
  3. Was deine Funktion zurückgibt, landet an derselben Position im neuen Array.
  4. Das Original bleibt unverändert.

Typischer Fehler

In map nichts zurückgeben, z.B. durch geschweifte Klammern ohne return. Dann ist das neue Array voller undefined. Außerdem map nur für Nebenwirkungen wie Loggen zu benutzen. Dafür gibt es forEach.

Wann welche Schreibweise?

map immer, wenn aus N Elementen N neue werden. Die Schleife brauchst du nur, wenn du unterwegs abbrechen willst.

Selbsttest

Wie viele Elemente hat das Ergebnis von [1, 2, 3, 4].map(n => n > 2)?

Lösung zeigen

Vier: [false, false, true, true]. map sortiert nie aus, die Länge bleibt immer gleich. Zum Aussortieren nimmst du filter.

filter und find#

filter gibt alle Treffer als Array, find den ersten Treffer oder undefined.

Kurz 
const open = todos.filter(t => !t.done);
const todo = todos.find(t => t.id === id);
Ausführlich 
const open = [];
for (const todo of todos) {
  if (todo.done === false) {
    open.push(todo);
  }
}

let found = undefined;
for (const todo of todos) {
  if (todo.id === id) {
    found = todo;
    break;
  }
}
Doku filter()find()findIndex()
Erklärung

Vorstellung

filter ist ein Sieb: Alles, was die Prüfung besteht, fällt in das neue Array. find ist ein Suchtrupp, der beim ersten Treffer aufhört und genau dieses eine Element meldet.

Was passiert, Schritt für Schritt

  1. Deine Funktion bekommt jedes Element und gibt true oder false zurück (oder truthy/falsy).
  2. filter sammelt alle Elemente mit true in einem neuen Array. Das kann auch leer sein.
  3. find gibt das erste Element mit true zurück und hört sofort auf. Findet es nichts, kommt undefined.

Typischer Fehler

Das Ergebnis von find ungeprüft benutzen: todos.find(...).title stürzt ab, wenn nichts gefunden wurde. Und filter(...)[0] statt find schreiben, was unnötig das ganze Array durchläuft.

Wann welche Schreibweise?

Die Methoden sind fast immer besser lesbar. Die Schleife zeigt, warum find schneller sein kann: wegen des break.

Selbsttest

Was gibt filter zurück, wenn nichts passt? Und was gibt find zurück?

Lösung zeigen

filter gibt ein leeres Array [] zurück, find gibt undefined zurück.

some und every#

Geben einen Boolean zurück: Trifft es auf mindestens eins zu, oder auf alle?

Kurz 
const anyOpen = todos.some(t => !t.done);
const allDone = todos.every(t => t.done);
Ausführlich 
let anyOpen = false;
for (const todo of todos) {
  if (todo.done === false) {
    anyOpen = true;
    break;
  }
}

let allDone = true;
for (const todo of todos) {
  if (todo.done === false) {
    allDone = false;
    break;
  }
}
Doku some()every()
Erklärung

Vorstellung

some fragt: Gibt es mindestens einen? every fragt: Sind es wirklich alle? Beide antworten nur mit Ja oder Nein.

Was passiert, Schritt für Schritt

  1. some geht die Elemente durch und stoppt beim ersten true. Das Ergebnis ist dann true.
  2. every stoppt beim ersten false. Das Ergebnis ist dann false.
  3. Läuft die Schleife ohne Abbruch durch, ist some false und every true.

Typischer Fehler

Leere Arrays: [].every(...) ist true, [].some(...) ist false. Das überrascht, ist aber logisch: Bei null Elementen gibt es keins, das die Bedingung verletzt.

Wann welche Schreibweise?

Ideal für UI-Zustände wie disabled={!items.some(i => i.selected)}. Viel klarer als filter(...).length > 0.

Selbsttest

Wie drückst du mit some aus, dass kein Todo erledigt ist?

Lösung zeigen

!todos.some(t => t.done). Gleichwertig ist todos.every(t => !t.done).

reduce: zusammenfassen#

Macht aus einem Array einen einzelnen Wert. acc ist das Zwischenergebnis, der zweite Parameter der Startwert.

Kurz 
const total = cart.reduce((sum, item) => sum + item.price * item.qty, 0);

const byCat = products.reduce((acc, p) => {
  (acc[p.category] ??= []).push(p);
  return acc;
}, {});
Ausführlich 
let total = 0;
for (const item of cart) {
  total = total + item.price * item.qty;
}

const byCat = {};
for (const product of products) {
  const key = product.category;
  if (byCat[key] === undefined) {
    byCat[key] = [];
  }
  byCat[key].push(product);
}
Doku reduce()Nullish-Zuweisung ??=
Erklärung

Vorstellung

reduce ist ein Schneeball, der einen Hang hinunterrollt. Er startet klein mit dem Startwert und nimmt bei jedem Element etwas auf, bis am Ende ein einziger Ball übrig ist.

Was passiert, Schritt für Schritt

  1. Der Startwert (hier 0 oder {}) wird zum ersten acc, dem Akkumulator.
  2. Für jedes Element wird deine Funktion mit (acc, element) aufgerufen.
  3. Was du zurückgibst, ist das acc für das nächste Element.
  4. Nach dem letzten Element ist acc das Ergebnis.
  5. ??= in der Kurzform heißt: Nur zuweisen, wenn links null oder undefined steht. So wird pro Kategorie genau einmal ein leeres Array angelegt.

Typischer Fehler

Den Startwert vergessen. Dann wird das erste Element zum Startwert, was bei Objekten (z.B. Warenkorb-Items) falsche Ergebnisse liefert. Oder return acc vergessen, dann ist acc im nächsten Schritt undefined.

Wann welche Schreibweise?

Für Summen ist reduce kurz und klar. Für Gruppierungen ist die Schleife oft lesbarer, und das ist völlig in Ordnung. reduce ist kein Pflichtprogramm.

Selbsttest

Was ergibt [1, 2, 3].reduce((acc, n) => acc + n, 10)?

Lösung zeigen

16. Start bei 10, dann 11, 13, 16.

Immutable Updates (React State)#

State nie direkt ändern, sondern immer ein neues Array erzeugen. Sonst merkt React die Änderung nicht.

Kurz 
// hinzufügen
setTodos([...todos, newTodo]);

// ein Element ändern
setTodos(todos.map(t =>
  t.id === id ? { ...t, done: !t.done } : t
));
Ausführlich 
// hinzufügen
const withNew = todos.slice(); // Kopie
withNew.push(newTodo);
setTodos(withNew);

// ein Element ändern
const updated = todos.map(function (todo) {
  if (todo.id === id) {
    const copy = Object.assign({}, todo);
    copy.done = !todo.done;
    return copy;
  }
  return todo;
});
setTodos(updated);
Doku Spread-SyntaxArrays im State aktualisieren (EN)
Erklärung

Vorstellung

React prüft State wie ein Postbote, der nur auf die Hausnummer schaut und nicht in die Wohnung. Stellst du nur die Möbel um (Mutation), merkt er nichts. Erst eine neue Adresse, also ein neues Array oder Objekt, löst ein Re-Render aus.

Was passiert, Schritt für Schritt

  1. [...todos, newTodo] erzeugt ein neues Array mit allen alten Elementen plus dem neuen.
  2. map erzeugt ebenfalls ein neues Array. Nur das betroffene Element wird durch eine Kopie ersetzt, die anderen werden unverändert übernommen.
  3. { ...t, done: !t.done } kopiert das Todo und überschreibt ein Feld.
  4. React vergleicht alte und neue Referenz, sieht den Unterschied und rendert neu.

Typischer Fehler

todos.push(newTodo); setTodos(todos); Das Array ist dasselbe Objekt, also passiert im UI nichts. Genauso bei todo.done = true direkt am State. Vorsicht auch bei sort() und reverse(), die das Original verändern.

Wann welche Schreibweise?

Spread ist in React der Standard. Die ausführliche Form zeigt, was dabei eigentlich passiert: erst kopieren, dann die Kopie ändern.

Selbsttest

Warum funktioniert const copy = todos; copy.push(x); setTodos(copy); nicht?

Lösung zeigen

copy = todos kopiert nicht das Array, sondern nur den Verweis. Beide Namen zeigen auf dasselbe Array, also sieht React keine neue Referenz.

Daten aus APIs sind fast immer Objekte, also lohnt sich Sicherheit hier besonders.

Destructuring#

Werte direkt in Variablen auspacken. Funktioniert bei Objekten {}, Arrays [] und in Funktionsparametern (React-Props).

Kurz 
const { name, age = 18 } = user;
const { id: userId } = user;
const [value, setValue] = useState(0);

function Card({ title, children }) { ... }
Ausführlich 
const name = user.name;
const age = user.age !== undefined ? user.age : 18;
const userId = user.id;

const state = useState(0);
const value = state[0];
const setValue = state[1];

function Card(props) {
  const title = props.title;
  const children = props.children;
  ...
}
Doku DestructuringProps an Komponenten übergeben (EN)
Erklärung

Vorstellung

Destructuring ist Auspacken nach Etikett: Du sagst, welche Fächer du aus dem Paket willst, und bekommst den Inhalt direkt in gleichnamige Variablen.

Was passiert, Schritt für Schritt

  1. { name, age = 18 } = user liest user.name und user.age. Ist age undefined, gilt 18.
  2. { id: userId } heißt: Nimm das Feld id, aber nenne die Variable userId.
  3. Bei Arrays zählt die Position, nicht der Name. Deshalb kannst du bei useState die Namen frei wählen.
  4. In Parametern wie ({ title }) wird das übergebene Objekt, in React die Props, direkt beim Aufruf ausgepackt.

Typischer Fehler

Destructuring von undefined stürzt ab: const { name } = undefined wirft einen TypeError, z.B. wenn API-Daten noch nicht geladen sind. Und Objekt- mit Array-Destructuring verwechseln: const { a, b } = [1, 2] ergibt zweimal undefined.

Wann welche Schreibweise?

In React fast immer Destructuring, weil man die Props sofort sieht. Die ausführliche Form hilft, wenn du nachvollziehen willst, woher ein Wert kommt.

Selbsttest

Welche Variable existiert nach const { id: userId } = user: id oder userId?

Lösung zeigen

Nur userId. Links vom Doppelpunkt steht der Feldname im Objekt, rechts der neue Variablenname.

Spread: Objekte kopieren#

Kopie erstellen und gezielt Felder überschreiben oder entfernen. Nur eine flache Kopie.

Kurz 
const updated = { ...user, age: 30 };

const { password, ...safeUser } = user;
Ausführlich 
const updated = Object.assign({}, user);
updated.age = 30;

const safeUser = Object.assign({}, user);
delete safeUser.password;
Doku Spread-SyntaxObject.assign()Objekte im State aktualisieren (EN)
Erklärung

Vorstellung

Spread schüttet den Inhalt eines Objekts in ein neues Objekt. Was danach kommt, überschreibt gleichnamige Felder, wie eine neue Schicht Farbe.

Was passiert, Schritt für Schritt

  1. { ...user } legt ein neues Objekt an und kopiert alle Felder von user hinein.
  2. age: 30 dahinter überschreibt das kopierte age. Die Reihenfolge entscheidet.
  3. { password, ...safeUser } = user zieht password heraus und packt den Rest in safeUser.
  4. Object.assign({}, user) macht dasselbe wie Spread, ist nur älter und länger.

Typischer Fehler

Spread kopiert nur flach. Verschachtelte Objekte wie user.address werden nicht kopiert, sondern geteilt. Änderst du copy.address.city, änderst du auch das Original.

Wann welche Schreibweise?

Spread ist der Standard. delete wie in der ausführlichen Form nur an einer Kopie benutzen, nie am Original oder am State.

Selbsttest

Was ist x.age bei const x = { age: 30, ...user }, wenn user.age 25 ist?

Lösung zeigen

25. Der Spread steht hinter age: 30 und überschreibt den Wert.

Über Objekte iterieren#

Object.entries macht aus einem Objekt ein Array aus [key, value]-Paaren.

Kurz 
const scores = { anna: 3, ben: 5 };
const lines = Object.entries(scores)
  .map(([name, s]) => `${name}: ${s}`);
Ausführlich 
const scores = { anna: 3, ben: 5 };
const lines = [];
for (const name in scores) {
  const score = scores[name];
  lines.push(name + ": " + score);
}
Doku Object.entries()for...infor...of
Erklärung

Vorstellung

Objekte sind keine Listen, darum kannst du nicht direkt map darauf aufrufen. Object.entries legt das Objekt wie eine Tabelle aus: jede Zeile ein Paar aus Schlüssel und Wert.

Was passiert, Schritt für Schritt

  1. Object.entries(scores) ergibt [["anna", 3], ["ben", 5]].
  2. Auf diesem Array funktioniert map wie gewohnt.
  3. ([name, s]) => ... packt jedes Paar per Array-Destructuring in zwei Variablen aus.
  4. for...in läuft direkt über die Schlüssel eines Objekts. Den Wert holst du dir mit scores[name].

Typischer Fehler

for...in und for...of verwechseln. for...in liefert Schlüssel (bei Arrays die Indizes als Strings), for...of liefert Werte und funktioniert nicht auf normalen Objekten.

Wann welche Schreibweise?

Object.entries plus map, wenn ein neues Array entstehen soll, z.B. JSX. for...in für einfache Durchläufe ohne Ergebnis-Array.

Selbsttest

Was passiert bei for (const x of { a: 1 })?

Lösung zeigen

Ein TypeError, weil ein normales Objekt nicht iterierbar ist. Du brauchst Object.entries, Object.keys oder for...in.

Shorthand und dynamische Keys#

Heißen Variable und Key gleich, reicht der Name einmal. [ ] im Objekt berechnet den Key. Klassiker im Formular-Handler.

Kurz 
const user = { name, age };

const handleChange = e =>
  setForm({ ...form, [e.target.name]: e.target.value });
Ausführlich 
const user = { name: name, age: age };

function handleChange(event) {
  const field = event.target.name;
  const value = event.target.value;
  const newForm = Object.assign({}, form);
  newForm[field] = value;
  setForm(newForm);
}
Doku Objekt-Initialisierer (Shorthand, berechnete Keys)
Erklärung

Vorstellung

Shorthand spart eine Wiederholung: Heißen Feld und Variable gleich, reicht der Name einmal. Eckige Klammern sind ein Platzhalter für einen Feldnamen, der erst zur Laufzeit feststeht.

Was passiert, Schritt für Schritt

  1. { name, age } wird intern zu { name: name, age: age }.
  2. Im Formular hat jedes Input ein name-Attribut, z.B. email.
  3. [e.target.name] setzt den Wert dieses Attributs als Schlüssel ein. So reicht ein einziger Handler für alle Felder.
  4. Der Spread davor übernimmt alle anderen Formularfelder unverändert.

Typischer Fehler

Die eckigen Klammern vergessen: { field: value } legt wörtlich ein Feld namens field an, statt den Inhalt der Variable zu nehmen.

Wann welche Schreibweise?

Ein generischer handleChange mit dynamischem Key spart bei großen Formularen viel doppelten Code.

Selbsttest

Was ist der Unterschied zwischen { [key]: "Berlin" } und { key: "Berlin" }, wenn key = "city"?

Lösung zeigen

Das erste ergibt { city: "Berlin" }, das zweite { key: "Berlin" }. Nur die eckigen Klammern werten die Variable aus.

Promises mit .then#

Ein Platzhalter für einen Wert, der später kommt. Jedes .then bekommt das Ergebnis des vorherigen.

Kurz 
fetch("/api/users")
  .then(res => res.json())
  .then(setUsers)
  .catch(console.error);
Ausführlich 
fetch("/api/users")
  .then(function (response) {
    return response.json();
  })
  .then(function (data) {
    setUsers(data);
  })
  .catch(function (error) {
    console.error(error);
  });
Doku Promises verwendenPromise
Erklärung

Vorstellung

Ein Promise ist ein Abholschein: fetch gibt dir sofort den Schein, die Ware kommt später. .then heißt: Wenn die Ware da ist, mach Folgendes damit.

Was passiert, Schritt für Schritt

  1. fetch startet den Request und gibt sofort ein Promise zurück. Der restliche Code läuft weiter, ohne zu warten.
  2. Kommt die Antwort, ruft JavaScript die Funktion im ersten .then mit dem Response-Objekt auf.
  3. response.json() liest den Body und gibt wieder ein Promise zurück. Das nächste .then wartet darauf.
  4. Tritt irgendwo ein Fehler auf, springt die Kette direkt zum .catch.

Typischer Fehler

Das return in einem .then vergessen. Dann bekommt das nächste .then undefined statt der Daten. Und: Code unterhalb der Kette läuft vor den Callbacks, nicht danach.

Wann welche Schreibweise?

.then(setUsers) funktioniert in der Kurzform, weil setUsers selbst eine Funktion ist, die die Daten als Argument nimmt. Man übergibt sie direkt, statt sie in eine weitere Funktion zu verpacken.

Selbsttest

In welcher Reihenfolge erscheinen die Logs: console.log("A"); fetch(url).then(() => console.log("B")); console.log("C");?

Lösung zeigen

A, C, B. Der Callback in .then läuft erst, wenn die Antwort da ist, und das ist immer nach dem restlichen synchronen Code.

async / await#

Hier ist await die kurze Form: Es macht dasselbe wie die .then-Kette, liest sich aber wie normaler Code.

Kurz 
const loadUser = async id => {
  try {
    const res = await fetch(`/api/users/${id}`);
    return await res.json();
  } catch (err) {
    console.error(err);
    return null;
  }
};
Ausführlich 
function loadUser(id) {
  return fetch("/api/users/" + id)
    .then(function (response) {
      return response.json();
    })
    .catch(function (error) {
      console.error(error);
      return null;
    });
}
Doku async functionawaittry...catch
Erklärung

Vorstellung

await heißt: Ich warte hier, bis der Abholschein eingelöst ist. Das gilt aber nur innerhalb dieser einen Funktion, der Rest der App läuft weiter.

Was passiert, Schritt für Schritt

  1. async vor einer Funktion bedeutet: Sie gibt immer ein Promise zurück.
  2. await pausiert nur diese Funktion, bis das Promise erfüllt ist, und liefert dann den Wert.
  3. Wird das Promise abgelehnt, wirft await einen Fehler, den try/catch auffängt.
  4. Wer loadUser aufruft, braucht selbst wieder await oder .then, um an den Wert zu kommen.

Typischer Fehler

await vergessen: const data = res.json() ist dann ein Promise und keine Daten. Oder await außerhalb einer async-Funktion benutzen. Das geht nur auf oberster Ebene in ES-Modulen.

Wann welche Schreibweise?

async/await ist heute Standard, weil es sich wie normaler Code von oben nach unten liest. Die .then-Version musst du trotzdem lesen können.

Selbsttest

Was bekommst du zurück, wenn du loadUser(1) ohne await aufrufst?

Lösung zeigen

Ein Promise. Eine async-Funktion gibt immer ein Promise zurück, auch wenn darin return null steht.

fetch mit POST und Fehlerprüfung#

fetch wirft bei 404 oder 500 keinen Fehler. res.ok musst du selbst prüfen.

Kurz 
const res = await fetch("/api/todos", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title }),
});
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const todo = await res.json();
Ausführlich 
const options = {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: title }),
};
const response = await fetch("/api/todos", options);

if (response.ok === false) {
  throw new Error("HTTP " + response.status);
}

const todo = await response.json();
Doku Verwenden der Fetch APIResponse.okJSON.stringify()
Erklärung

Vorstellung

Ein POST-Request ist ein Brief: method ist die Versandart, headers steht auf dem Umschlag (z.B. „Inhalt ist JSON“), und body ist der Brief selbst, der als Text verschickt wird.

Was passiert, Schritt für Schritt

  1. JSON.stringify wandelt das Objekt in einen JSON-String um, weil HTTP nur Text überträgt.
  2. Der Content-Type-Header sagt deinem Backend, z.B. express.json(), wie es den Body lesen soll.
  3. fetch gilt als erfolgreich, sobald überhaupt eine Antwort kommt, egal mit welchem Status.
  4. Darum res.ok prüfen. Es ist nur bei Status 200 bis 299 true.
  5. Erst danach den Body mit res.json() lesen.

Typischer Fehler

Das Objekt ohne JSON.stringify als body übergeben, dann kommt beim Server [object Object] an. Oder den Header vergessen, dann ist req.body im Backend leer. Diesen Fehler kannst du jetzt von beiden Seiten aus debuggen.

Wann welche Schreibweise?

Ein separates options-Objekt hilft, wenn du Optionen wiederverwenden oder loggen willst. In echten Projekten lohnt sich eine kleine Helferfunktion wie api(url, data).

Selbsttest

Dein Backend antwortet mit Status 404. Landet fetch im catch?

Lösung zeigen

Nein. fetch wirft nur bei Netzwerkfehlern, z.B. wenn der Server nicht erreichbar ist oder CORS blockt. Ein 404 ist eine gültige Antwort, deshalb die Prüfung von res.ok.

Promise.all: parallel laden#

Mehrere Requests gleichzeitig starten und auf alle warten. Scheitert einer, scheitert alles.

Kurz 
const [users, posts] = await Promise.all([
  fetch("/api/users").then(r => r.json()),
  fetch("/api/posts").then(r => r.json()),
]);
Ausführlich 
const usersPromise = fetch("/api/users").then(function (r) {
  return r.json();
});
const postsPromise = fetch("/api/posts").then(function (r) {
  return r.json();
});

const results = await Promise.all([usersPromise, postsPromise]);
const users = results[0];
const posts = results[1];
Doku Promise.all()Promise.allSettled()
Erklärung

Vorstellung

Statt erst zum Bäcker und dann zum Metzger zu gehen, schickst du zwei Leute gleichzeitig los und wartest, bis beide zurück sind.

Was passiert, Schritt für Schritt

  1. Beide fetch-Aufrufe starten sofort, noch bevor await wartet.
  2. Promise.all bekommt ein Array von Promises und gibt ein einziges Promise zurück.
  3. Es ist erfüllt, wenn alle fertig sind. Die Ergebnisse stehen in derselben Reihenfolge wie die Eingabe, egal wer zuerst fertig war.
  4. Schlägt eines fehl, schlägt sofort das ganze Promise.all fehl.

Typischer Fehler

Versehentlich nacheinander laden: const a = await fetch(...); const b = await fetch(...); dauert doppelt so lange, obwohl die Requests unabhängig sind. Ist ein Teilergebnis optional, ist Promise.allSettled die bessere Wahl.

Wann welche Schreibweise?

Die Kurzform mit Array-Destructuring ist Standard. Die ausführliche Form zeigt, dass das Ergebnis einfach ein Array ist.

Selbsttest

Request A dauert 2 Sekunden, B dauert 3. Wie lange dauert es mit zwei await nacheinander, und wie lange mit Promise.all?

Lösung zeigen

Nacheinander 5 Sekunden. Mit Promise.all etwa 3 Sekunden, also so lange wie der langsamste Request.

Named Exports gibt es beliebig viele, Import mit gleichem Namen in {}. Default nur einen pro Datei, Name beim Import frei wählbar.

Kurz

Ausführlich

function formatPrice(price) {
  return price.toFixed(2) + " €";
}
function api() { ... }

import { formatPrice } from "./utils.js";
Doku JavaScript-Moduleexportimport
Erklärung

Vorstellung

Eine Datei ist ein Laden. Named Exports sind die Artikel im Regal, jeder mit festem Namen. Der Default Export ist das Hauptprodukt im Schaufenster, das du beim Mitnehmen beliebig nennen darfst.

Was passiert, Schritt für Schritt

  1. export vor einer Deklaration exportiert sie direkt unter ihrem Namen.
  2. Alternativ definierst du erst alles und exportierst am Ende gesammelt mit export { ... }.

Genau einen. Named Exports beliebig viele.

Klassen#

Im React-Frontend selten, im Backend (Services, eigene Fehler) häufig. Felder können direkt in der Klasse stehen statt im constructor.

const u = new User("Lea");

      return true;
    }
    return false;
  }
}

Eine Klasse ist ein Bauplan, und new baut nach diesem Plan ein konkretes Objekt, eine Instanz. Jede Instanz hat eigene Daten, teilt sich aber die Methoden des Bauplans.

Was passiert, Schritt für Schritt

  1. new User("Lea") legt ein leeres Objekt an und ruft den constructor auf.

Event Delegation#

Ein Listener auf dem Eltern-Element statt einer pro Button. Welcher geklickt wurde, verrät event.target.

Kurz 
list.addEventListener("click", e => {
  const btn = e.target.closest("button[data-id]");
  if (btn) deleteTodo(btn.dataset.id);
});
Ausführlich 
function handleListClick(event) {
  const button = event.target.closest("button[data-id]");
  if (button === null) {
    return;
  }
  const id = button.getAttribute("data-id");
  deleteTodo(id);
}

list.addEventListener("click", handleListClick);
Doku Event BubblingElement.closest()dataset
Erklärung

Vorstellung

Statt jedem Tisch im Restaurant einen eigenen Kellner zu geben, steht ein Kellner im Raum und schaut, von welchem Tisch gerufen wurde.

Was passiert, Schritt für Schritt

  1. Ein Klick auf einen Button steigt durch alle Eltern-Elemente nach oben bis zum Dokument (Event Bubbling).
  2. Darum bekommt der Listener auf der Liste auch Klicks auf ihre Kinder mit.
  3. event.target ist das Element, das tatsächlich geklickt wurde, eventuell nur ein Icon im Button.
  4. closest("button[data-id]") sucht von dort aus nach oben den passenden Button oder gibt null zurück.
  5. dataset.id liest das Attribut data-id aus.

Typischer Fehler

event.target direkt benutzen, ohne closest. Klickt jemand auf ein <span> im Button, ist das Ziel der Span und dataset.id ist undefined.

Delegation lohnt sich bei Listen, die sich ändern: Neue Elemente funktionieren automatisch, ohne neue Listener. In React übernimmt das Framework das intern für dich.

Selbsttest

Warum funktioniert Delegation auch für Listenelemente, die erst später hinzukommen?

Lösung zeigen

Weil der Listener am Eltern-Element hängt, das schon existiert. Neue Kinder schicken ihre Klicks per Bubbling automatisch dorthin.

Debounce#

Funktion erst ausführen, wenn eine Weile Ruhe ist, z.B. bei einem Suchfeld. Nutzt eine Closure für timer.

Kurz 
const debounce = (fn, delay = 300) => {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
};
Ausführlich 
function debounce(fn, delay) {
  if (delay === undefined) {
    delay = 300;
  }
  let timer = null;

  function debounced(value) {
    clearTimeout(timer);
    timer = setTimeout(function () {
      fn(value);
    }, delay);
  }

  return debounced;
}
Doku DebounceThrottlesetTimeout()
Erklärung

Vorstellung

Wie ein Aufzug, der wartet, bis keiner mehr einsteigt: Jede neue Person setzt den Türtimer zurück. Erst wenn kurz Ruhe ist, fährt er los.

Was passiert, Schritt für Schritt

  1. debounce gibt eine neue Funktion zurück, die sich timer per Closure merkt.
  2. Bei jedem Tastendruck wird der alte Timer mit clearTimeout gelöscht.
  3. Dann startet ein neuer Timer.
  4. Nur wenn innerhalb von delay Millisekunden kein neuer Tastendruck kommt, läuft der Timer ab und fn wird ausgeführt.
  5. Ergebnis: Wer „berlin“ tippt, löst einen Request aus statt sechs.

Typischer Fehler

In React die Debounce-Funktion bei jedem Render neu erzeugen. Dann hat jede Version ihren eigenen timer, und nichts wird abgebrochen. Lösung: mit useMemo oder useRef stabil halten oder einen fertigen Hook nutzen.

Wann welche Schreibweise?

Die ausführliche Version reicht nur ein Argument durch. Die kurze reicht mit ...args beliebig viele durch und ist dadurch universeller.

Selbsttest

Was ist der Unterschied zwischen Debounce und Throttle?

Lösung zeigen

Debounce wartet auf Ruhe und feuert einmal am Ende. Throttle feuert höchstens einmal pro Zeitintervall, auch wenn ununterbrochen Events kommen, z.B. beim Scrollen.

Guard Clauses#

Hier ist es umgekehrt: Die kurze Variante mit frühen returns ist die empfohlene, die verschachtelte ist schwerer zu lesen.

Kurz 
function checkout(cart, user) {
  if (!user) return redirect("/login");
  if (!cart.length) return showError("Korb leer");

  placeOrder(cart, user);
}
Ausführlich 
function checkout(cart, user) {
  if (user) {
    if (cart.length > 0) {
      placeOrder(cart, user);
    } else {
      showError("Korb leer");
    }
  } else {
    redirect("/login");
  }
}
Doku returnif...else
Erklärung

Vorstellung

Ein Türsteher prüft am Eingang: Wer kein Ticket hat, wird sofort abgewiesen. Wer durchkommt, ist garantiert berechtigt, drinnen muss niemand mehr kontrollieren.

Was passiert, Schritt für Schritt

  1. Jede Bedingung prüft einen Fehlerfall und beendet die Funktion sofort mit return.
  2. Nach allen Guards steht fest, dass alle Voraussetzungen erfüllt sind.
  3. Der eigentliche Zweck der Funktion, der Happy Path, steht ganz unten und ohne Einrückung.
  4. Die verschachtelte Variante macht dasselbe, aber Bedingung und Fehlerbehandlung liegen weit auseinander.

Typischer Fehler

Das return vergessen: Dann wird zwar der Fehler gezeigt, aber der Code läuft weiter und bestellt trotzdem. Im Backend ist es derselbe Klassiker: res.status(400).json(...) ohne return führt zu „Cannot set headers after they are sent“.

Wann welche Schreibweise?

Guard Clauses sind hier die empfohlene Variante. Faustregel: Ab mehr als zwei Ebenen Einrückung prüfen, ob sich Bedingungen umdrehen und früh beenden lassen.

Wo begegnen dir Guard Clauses im Backend ständig?

Lösung zeigen

In Express-Routen und Middleware: if (!req.user) return res.status(401)..., if (!item) return res.status(404)... und erst danach die eigentliche Logik.

Lade-, Fehler- und Daten-Zustand#

Jeder Request hat drei mögliche Ausgänge, und das UI sollte alle drei zeigen.

Kurz 
useEffect(() => {
  fetch("/api/todos")
    .then(r => { if (!r.ok) throw new Error(r.status); return r.json(); })
    .then(setData)
    .catch(setError)
    .finally(() => setLoading(false));
}, []);

if (loading) return <Spinner />;
if (error) return <p>Fehler: {error.message}</p>;
return <TodoList todos={data} />;
Ausführlich 
useEffect(function () {
  async function loadTodos() {
    try {
      const response = await fetch("/api/todos");
      if (response.ok === false) {
        throw new Error("HTTP " + response.status);
      }
      const todos = await response.json();
      setData(todos);
    } catch (err) {
      setError(err);
    } finally {
      setLoading(false);
    }
  }
  loadTodos();
}, []);

if (loading) {
  return <Spinner />;
}
if (error) {
  return <p>Fehler: {error.message}</p>;
}
return <TodoList todos={data} />;

Erklärung

Vorstellung

Jeder Request ist wie eine Bestellung: Sie ist unterwegs (Laden), sie ist schiefgegangen (Fehler) oder sie ist angekommen (Daten). Das UI braucht für jeden dieser drei Zustände eine eigene Ansicht.

Was passiert, Schritt für Schritt

  1. Startzustand: loading ist true, es gibt keine Daten und keinen Fehler.
  2. useEffect mit leerem Abhängigkeits-Array [] startet den Request einmal nach dem ersten Render.
  3. Bei Erfolg landen die Daten per setData im State, bei einem Fehler per setError.
  4. finally setzt loading in beiden Fällen auf false.
  5. Die frühen returns beim Rendern sind Guard Clauses: erst Laden, dann Fehler, dann der Normalfall.

Typischer Fehler

Die Effect-Funktion selbst async machen, also useEffect(async () => ...). React erwartet als Rückgabe eine Cleanup-Funktion, kein Promise. Deshalb gibt es die innere async function loadTodos().

Wann welche Schreibweise?

Bei mehreren Schritten ist die async/await-Variante lesbarer. In größeren Projekten übernehmen Bibliotheken wie TanStack Query genau dieses Muster für dich.

Selbsttest

Was passiert, wenn du if (loading) return <Spinner /> weglässt und direkt data.map(...) renderst?

Lösung zeigen

Beim ersten Render ist data noch null, und data.map wirft einen TypeError. Deshalb muss der Ladezustand zuerst abgefangen werden.
